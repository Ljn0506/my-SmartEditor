# 智能编辑器 — 本地知识库搭建框架文档

| 项目 | 内容 |
|-----|------|
| 文档版本 | v1.0 |
| 创建日期 | 2026-04-27 |
| 适用范围 | 企业信息安全售前/商务团队 NAS 知识库 |
| 配套系统 | 智能文档编写工具（Tauri 桌面应用）|

---

## 1. 概述

### 1.1 目的

本文档定义 NAS 共享盘上知识库的组织规范，确保：

1. 历史文档可被智能编辑器高效扫描、分类、检索
2. 团队多人协作时，文档存放位置统一、可预期
3. 新员工能快速定位所需素材，减少重复编写
4. 知识沉淀有明确入口，避免优秀方案散落于个人电脑

### 1.2 适用范围

| 适用 | 不适用 |
|-----|-------|
| NAS 共享盘上的投标文档、技术方案、商务模板 | 个人电脑本地文件 |
| 经脱敏处理后可复用的历史项目文档 | 含敏感客户信息的原始投标文件（未脱敏） |
| 公司资质、产品资料、案例库等通用素材 | 临时工作草稿、过程版本文件 |

### 1.3 核心原则

1. **四级分类，三级目录**：四维分类模型中，三个维度用文件夹层级表达，一个维度用文件名前缀表达
2. **文件名即元数据**：通过规范的命名，让智能编辑器无需打开文件即可推断分类
3. **不改内容，只改位置**：迁移时只移动/重命名文件，不修改文件内部，保留原始排版
4. **通用素材独立**：跨项目复用的内容（资质、案例、产品资料）独立存放，避免重复拷贝

## 2. 四维分类模型

智能编辑器采用四维分类模型对知识库内容进行组织：

| 维度 | 取值 | 说明 |
|-----|------|------|
| **文档属性** | 投标应答、技术方案、实施方案、合同协议、汇报材料 | 文档的用途和形式 |
| **业务领域** | 网络安全、应用安全、数据安全、安全运营、安全管理 | 文档所属的安全专业方向 |
| **内容模块** | 技术方案、商务条款、实施计划、资质证明、偏离说明、案例介绍 | 文档内部的功能模块 |
| **项目阶段** | 方案阶段、投标阶段、合同阶段 | 项目生命周期阶段 |

**安全层级**（业务领域子维度，可选）：

| 层级 | 典型内容 |
|-----|---------|
| 检测层 | 漏洞扫描、渗透测试、代码审计、基线核查 |
| 防御层 | 防火墙、WAF、IDS/IPS、终端安全、数据防泄漏 |
| 分析层 | SOC、态势感知、SIEM、威胁情报、日志分析 |
| 治理层 | 安全管理体系、等保合规、数据治理、安全运营 |

## 3. 目录结构规范

### 3.1 顶层架构

```
/Volumes/NAS/知识库/                    # 根目录，建议统一命名
├── 00-通用素材/                         # 跨阶段、跨项目复用
├── 01-方案阶段/                         # 项目前期：需求分析、方案设计
├── 02-投标阶段/                         # 项目中期：投标应答、商务谈判
└── 03-合同阶段/                         # 项目后期：合同交付、实施验收
```

**说明**：
- 一级目录按 **项目阶段** 划分，与智能编辑器的"项目阶段"维度对齐
- `00-通用素材` 不隶属于任何阶段，所有项目均可引用
- 编号前缀（00/01/02/03）确保目录按逻辑顺序排列

### 3.2 二级目录（业务领域）

每个项目阶段下，按 **业务领域** 划分为五个方向：

```
01-方案阶段/
├── 01-网络安全/                         # 等保、网络安全建设、边界防护
├── 02-应用安全/                         # 渗透测试、代码审计、SDL
├── 03-数据安全/                         # 数据分类分级、数据防泄漏、隐私保护
├── 04-安全运营/                         # SOC、态势感知、威胁情报、MSS
└── 05-安全管理/                         # 等保合规、安全体系建设、风险评估
```

**说明**：
- 编号 01-05 对应五大业务领域，固定不变
- 如果某领域内容较少，保留空目录占位，便于后续扩展
- 通用性强的内容（如公司介绍），放入 `00-通用素材`

### 3.3 三级目录（内容模块）

每个业务领域下，按 **内容模块** 细分：

**方案阶段**的三级目录：
```
01-方案阶段/01-网络安全/
├── 01-技术方案/                         # 技术架构、设计思路、产品选型
├── 02-实施方案/                         # 实施步骤、交付计划、验收标准
└── 03-实施计划/                         # 项目进度、里程碑、资源安排
```

**投标阶段**的三级目录：
```
02-投标阶段/01-网络安全/
├── 01-技术方案/                         # 投标技术方案正文
├── 02-商务条款/                         # 报价、付款方式、工期、维保
├── 03-偏离说明/                         # 偏离表、差异分析
├── 04-资质证明/                         # 公司业绩、资质证书、人员简历
└── 05-投标应答/                         # 点对点应答、逐条响应
```

**合同阶段**的三级目录：
```
03-合同阶段/01-网络安全/
├── 01-技术方案/                         # 合同技术附件、详细设计
├── 02-商务条款/                         # 合同商务条款、SLA、变更管理
└── 03-实施计划/                         # 项目交付计划、验收流程
```

**说明**：
- 投标阶段的内容模块最多（5个），因为投标文件通常由多个独立文件组成
- 方案阶段和合同阶段的内容模块较少，聚焦核心交付物

### 3.4 通用素材目录结构

```
00-通用素材/
├── 01-公司资质/
│   ├── 营业执照/
│   ├── 资质证书/                        # 等保测评、CNCERT、ISO 等
│   ├── 安全资质/                        # 安全服务资质、产品资质
│   └── 人员资质/                        # 工程师证书、专家简历
├── 02-案例库/
│   ├── 金融行业/
│   ├── 政府行业/
│   ├── 能源行业/
│   ├── 医疗行业/
│   └── 教育行业/
├── 03-产品资料/
│   ├── 防火墙/
│   ├── WAF/
│   ├── 态势感知/
│   ├── SOC/
│   ├── 漏洞扫描/
│   └── 数据防泄漏/
└── 04-商务模板/
    ├── 报价单模板/
    ├── 合同模板/
    ├── 承诺函模板/
    └── 授权书模板/
```

**说明**：
- 通用素材按"素材类型"组织，不按业务领域或项目阶段划分
- 案例库按行业细分，便于投标时快速找到同行业案例
- 产品资料按产品名称细分，每个产品可包含白皮书、彩页、配置指南

## 4. 文件命名规范

### 4.1 完整命名格式

```
【文档属性】[安全层级] 文件标题 - 补充说明.扩展名
```

**示例**：
```
【技术方案】[防御] 防火墙部署设计方案 - 某银行项目.docx
【投标应答】 等保2.0三级技术方案 - 点对点应答.docx
【商务条款】 年度安全运维服务报价单.xlsx
【汇报材料】 2025年度安全运营工作总结.pptx
```

### 4.2 文档属性前缀（必填）

| 前缀 | 文档属性 | 使用场景 |
|------|---------|---------|
| `【投标应答】` | 投标应答 | 针对招标要求的逐条响应文件 |
| `【技术方案】` | 技术方案 | 技术架构、实现方案、设计文档 |
| `【实施方案】` | 实施方案 | 实施步骤、交付计划、验收方案 |
| `【合同协议】` | 合同协议 | 合同正文、技术附件、SLA 协议 |
| `【汇报材料】` | 汇报材料 | PPT 汇报、总结材料、演示文档 |

**说明**：
- 前缀使用中文全角方括号 `【】`，便于肉眼识别和脚本解析
- 前缀位于文件名最开头，智能编辑器扫描时优先读取前缀推断文档属性

### 4.3 安全层级标注（可选）

| 标注 | 安全层级 | 适用内容 |
|------|---------|---------|
| `[检测]` | 检测层 | 漏洞扫描、基线核查、渗透测试 |
| `[防御]` | 防御层 | 防火墙、WAF、终端安全、数据防泄漏 |
| `[分析]` | 分析层 | SOC、态势感知、SIEM、威胁情报 |
| `[治理]` | 治理层 | 安全管理体系、等保合规、数据治理 |

**说明**：
- 安全层级标注使用半角方括号 `[]`，紧跟在文档属性前缀之后
- 同一文档涉及多个层级时，可标注多个，如 `[防御][分析]`
- 通用性强的文档（如公司资质）不需要安全层级标注

### 4.4 文件标题（必填）

- 使用简洁、描述性的中文标题
- 避免使用无意义的编号（如 `方案v3_final_最终版.docx`）
- 如需版本管理，在标题后加 `- v1.0`、`- v2.0`
- 避免使用过长的标题（建议不超过 30 个汉字）

### 4.5 补充说明（可选）

- 用于区分同一主题下的多个文件
- 常见补充说明：`点对点应答`、`简化版`、`详细版`、`脱敏版`、`参考版`
- 使用连字符 `-` 与标题分隔

### 4.6 扩展名规范

| 扩展名 | 文件类型 | 说明 |
|-------|---------|------|
| `.docx` | Word 文档 | 首选格式，便于智能编辑器解析 |
| `.pdf` | PDF 文档 | 用于对外发布、不可编辑的版本 |
| `.xlsx` | Excel 表格 | 报价单、偏离表、评审索引等 |
| `.pptx` | PowerPoint | 汇报材料、演示文档 |
| `.md` | Markdown | 技术笔记、轻量文档（可选） |
| `.txt` | 纯文本 | 临时记录、日志（不建议长期存放） |

**说明**：
- 尽量避免使用 `.doc`（旧版 Word），智能编辑器对 `.docx` 解析效果更好
- 同一内容如有 `.docx` 和 `.pdf` 两个版本，优先存放 `.docx`

## 6. 现有文件迁移流程

### 6.1 迁移前准备

1. **清点存量**：统计当前 NAS 上的文档数量、类型、分布
2. **评估工作量**：估算需要人工确认分类的文件数量
3. **分配责任人**：按业务领域分配迁移责任人（如应用安全文档由应用安全团队负责）
4. **备份原始数据**：迁移前完整备份 NAS 原始目录，防止误操作

### 6.2 迁移步骤

```
步骤 1：创建新目录结构（空文件夹）
    │
    ▼
步骤 2：编写脚本自动扫描现有文件，基于文件名/路径推断分类
    │
    ▼
步骤 3：生成迁移清单（CSV/Excel），列出每个文件的建议目标位置
    │
    ▼
步骤 4：责任人审核迁移清单，修正分类错误的文件
    │
    ▼
步骤 5：执行迁移（脚本自动移动 + 人工处理异常）
    │
    ▼
步骤 6：验证迁移结果（抽样检查 + 智能编辑器扫描测试）
    │
    ▼
步骤 7：发布新目录结构，通知团队更新书签/快捷方式
```

### 6.3 迁移脚本参考逻辑

```python
# 伪代码：自动分类推断
for file in nas_files:
    # 1. 从路径推断项目阶段、业务领域、内容模块
    stage = map_stage_from_path(file.parent.parent.parent)  # 一级目录
    domain = map_domain_from_path(file.parent.parent)       # 二级目录
    module = map_module_from_path(file.parent)              # 三级目录

    # 2. 从文件名推断文档属性、安全层级
    attr = extract_attr_from_filename(file.name)            # 【xxx】前缀
    layer = extract_layer_from_filename(file.name)          # [xxx] 标注

    # 3. 生成建议目标路径
    suggested_path = f"/知识库/{stage}/{domain}/{module}/"

    # 4. 如果文件名缺少前缀，建议添加
    if not attr:
        suggested_name = f"【待确认】{file.name}"
```

### 6.4 常见问题处理

| 问题 | 处理方案 |
|------|---------|
| 文件同时属于多个业务领域 | 放入最相关的领域，或在另一领域创建快捷方式/链接 |
| 文件名无法推断分类 | 放入 `00-通用素材/待分类/`，由责任人定期整理 |
| 同一文件有多个版本 | 保留最新版本，旧版本移入 `00-通用素材/归档/` |
| 文件内容跨多个内容模块 | 以文件主体内容为准，或拆分为多个文件 |
| 个人工作草稿 | 不放入知识库，建议存放于个人工作区 |

## 7. 维护规范

### 7.1 新增文档

1. **先确定分类**：上传前明确文档的四维分类（项目阶段 × 业务领域 × 内容模块 × 文档属性）
2. **按规范命名**：确保文件名包含文档属性前缀
3. **放入正确目录**：严格按照目录结构存放，不放根目录或临时文件夹
4. **通知团队**：新增重要文档后，在团队群/知识库公告中同步

### 7.2 文档更新

1. **版本管理**：更新时保留旧版本（移入归档目录），新版本按规范命名
2. **更新标签**：如文档内容变化导致分类变化，同步移动到新目录
3. **记录变更**：在文档内或团队 Wiki 中记录重大变更

### 7.3 定期清理

| 周期 | 清理内容 |
|------|---------|
| 每月 | 清理临时文件、过程版本、重复文件 |
| 每季度 | 检查 `00-通用素材/待分类/` 中的文件，完成分类 |
| 每年 | 归档过时方案（如已废止的产品方案），更新资质证书 |

### 7.4 权限管理

| 目录 | 建议权限 |
|------|---------|
| `00-通用素材/` | 全员只读，指定人员可写 |
| `01-方案阶段/` | 售前/方案团队读写 |
| `02-投标阶段/` | 售前/商务团队读写 |
| `03-合同阶段/` | 项目交付团队读写 |

## 8. 与智能编辑器的对接说明

### 8.1 扫描方式

智能编辑器通过以下方式读取 NAS 知识库：

1. **路径扫描**：遍历 NAS 目录，根据文件夹层级推断分类
2. **文件名解析**：提取前缀和标注，补充文档属性和安全层级
3. **内容解析**：对命中的文件，调用解析引擎提取纯文本用于全文检索

### 8.2 准确率预估

| 推断方式 | 准确率 | 说明 |
|---------|-------|------|
| 仅路径推断 | ~85% | 目录结构规范后，阶段/领域/模块基本准确 |
| 路径 + 文件名 | ~90% | 加上前缀和标注，文档属性和安全层级也准确 |
| 路径 + 文件名 + AI | ~95% | AI 辅助确认，处理边界情况 |

### 8.3 未规范文件的处理

对于不符合命名规范或目录结构的文件：

1. **智能编辑器**会尝试基于文件名关键词进行 fallback 推断
2. **导入向导**中会提示用户手动确认分类
3. **建议**：定期将未规范文件纳入规范，提升整体准确率
