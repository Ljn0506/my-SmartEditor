## 附录 B：NAS Scanner v1.0 规范偏离记录

> 记录人：kimi_coder_Xin  
> 日期：2026-05-18  
> 关联任务：Wave 1 — 2.1-2.6 NAS Scanner 分类规范对齐

### 偏离 1：ContentModule 新增 ProductMaterial 变体

**规范要求**：通用素材目录下需支持"产品资料"分类。  
**原有实现**：`ContentModule` enum 仅包含 `TechnicalProposal` / `BusinessTerms` / `ImplementationPlan` / `QualificationProof` / `DeviationExplanation` / `CaseIntroduction` / `BidResponse`，无"产品资料"对应变体。  
**本次修改**：在 `src-tauri/src/models.rs` 的 `ContentModule` 中新增 `ProductMaterial = "产品资料"`。  
**影响评估**：
- 数据库兼容：数据库存储字符串值，新增变体不影响已有数据读取。
- 代码兼容：新增变体在 `category.rs` 的 match 中已覆盖，无 exhaustive match 编译错误。
- 偏离原因：规范 v1.0 定义了通用素材的四种类型（资质/案例/产品资料/商务模板），但早期 enum 设计遗漏了"产品资料"。

### 偏离 2：通用素材 BusinessDomain 设计为 None

**规范要求**：通用素材下文件独立分类。  
**本次实现**：`00-通用素材/` 下文件的 `BusinessDomain` 返回 `None`，不 fallback 到文件名关键词推断。  
**偏离原因**：规范未明确通用素材的"业务领域"如何映射。资质证明、案例介绍、产品资料、商务模板均属于跨领域通用内容，不特定于网络安全/应用安全/数据安全等单一领域。若强制 fallback 到 `NetworkSecurity`，会造成误导性分类。  
**建议**：如需为通用素材指定业务领域，建议在通用素材二级目录下再细分，或在前端展示时统一标记为"通用"。

### 偏离 3：路径推断支持任意深度 NAS 根目录

**规范要求**：一级目录 `01-方案阶段/02-投标阶段/03-合同阶段` 必须正确映射。  
**原有实现**：`category.rs` 使用固定的 `components.get(1)/get(2)/get(3)` 访问各级目录，假设文件路径从固定深度的根目录开始（如 `/data/01-方案阶段/...`）。  
**本次修改**：引入 `find_phase_root` 函数，遍历路径组件找到第一个匹配的项目阶段目录作为锚点，支持任意深度的 NAS 根目录（如 `/Users/ljn/NAS/01-方案阶段/...` 或 `/mnt/remote/nas/02-投标阶段/...`）。  
**偏离原因**：早期实现未考虑 NAS 挂载路径的深度不确定性。本次修改为增强健壮性，不改变规范语义。
