# 工作流重塑设计文档：需求驱动式文档生成

## 1. 核心工作流

```
用户上传招标文件
    ↓
[解析] 识别文件类型、提取需求要点
    ↓
[分析] 判断需要生成哪些文档（技术方案、商务响应、实施计划等）
    ↓
[生成] 基于本地知识库，按章节生成粗粒度卡片
    │   ├── 技术方案卡片（自动生成）
    │   └── 商务条款卡片（人机协作：先生成草稿，人确认后定稿）
    ↓
[组装] 用户选择/调整卡片 → 组装成完整文档
    ↓
[一致性检查] 确保多份文档之间的参数、承诺对齐
    ↓
[校对] 偏离检查 + 格式检查 + 内容自查
    ↓
[导出] 输出最终文件
```

## 2. 生成策略

### 2.1 技术方案（全自动）
- 根据招标需求直接匹配知识库素材
- AI 按章节生成卡片，每张卡片 = 一个章节（如"3.1 系统架构"）
- 一次可生成多个技术文件（如主方案 + 子系统方案）
- 关键约束：**同一次生成的多个文件之间要避免内容重复、参数矛盾**

### 2.2 商务响应（人机协作）
- 先生成商务条款草稿卡片
- 用户逐张确认/修改/替换
- 敏感条款（报价、工期、承诺）高亮提示人工审核

### 2.3 卡片结构
```
Card {
  id: string,
  chapter: string,           // 章节编号，如 "3.1"
  title: string,             // 章节标题
  content: string,           // 生成的正文
  source_refs: string[],     // 引用的知识库素材来源
  document_target: string,   // 目标文档（技术方案/商务响应/实施计划）
  status: "draft" | "confirmed" | "rejected",
  generated_by: "ai" | "manual" | "template",
  related_cards: string[],   // 关联卡片（用于一致性检查）
}
```

## 3. 多文件同时生成的一致性保证

### 3.1 一致性维度
- **参数一致**：技术方案中说"QPS 10000"，商务报价中也必须是 10000
- **承诺一致**：技术方案承诺"7×24 响应"，售后服务中不能变成"工作日"
- **时间一致**：实施计划说"3 个月交付"，合同中工期也必须是 3 个月
- **人员一致**：技术方案中项目经理是"张三"，资质证明中不能是"李四"

### 3.2 实现策略
- 在生成阶段维护一个**全局参数表**（Key-Value），所有卡片生成时引用同一套参数
- 生成后走一致性检查命令（可复用校对功能中的"自相矛盾"检查，跨文档版本）
- 商务条款卡片中涉及的数字、人名、工期等字段，与技术方案卡片做交叉校验

## 5. 与现有功能的衔接

### 5.1 知识库（NAS）
- NAS 扫描的历史素材作为生成卡片的参考源
- 每张卡片标注引用了哪些历史素材（source_refs）
- 用户可点击"换一版"让 AI 基于不同素材重新生成

### 5.2 校对功能（正在开发）
- 卡片全部确认后，组装成完整文档
- 然后触发校对流程（偏离检查 + 自查 + 格式）
- 校对结果中的问题直接关联到具体卡片，方便定位修改

### 5.3 偏离检查
- 偏离检查在组装后的完整文档上执行
- 但也可以提前在卡片级别做预检（可选优化）

## 6. 技术边界与风险

| 风险点 | 影响 | 缓解策略 |
|--------|------|----------|
| AI 生成质量不稳定 | 技术方案可能出错 | 允许用户逐张编辑 + 强制校对 |
| 多文件一致性难以保证 | 参数矛盾导致废标 | 全局参数表 + 交叉校验命令 |
| 生成速度太慢 | 用户体验差 | 卡片级异步生成，先出大纲再填内容 |
| 知识库素材不足 | 生成内容空泛 | 冷启动时允许用户手动补充关键素材 |

## 7. 实施顺序建议

这是一个大改动，建议分阶段：

**Phase 1（当前）**: 完成校对功能开发（Xin 正在进行）
**Phase 2**: 智能生成 Tab MVP
  - 技术方案自动生成（单文件）
  - 粗粒度卡片展示
  - 基础一致性检查
**Phase 3**: 多文件同时生成 + 商务人机协作
  - 同时生成技术+商务文件
  - 全局参数表
  - 跨文档一致性检查
**Phase 4**: 模板库完全下线
  - 前端移除 LibraryTab
  - 数据库保留作为知识库数据源
